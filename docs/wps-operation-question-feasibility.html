学测 WPS 操作题集成可行性分析报告

样本题目：《w市人口密度数据分析表》—— 合并居中 / 公式计算 / 函数汇总 / 插入柱形图
评估对象：西高中趣味学习平台（XGPY）v2.7.1
2026-10-10 结论：可集成 建议分期：一期 1~2 周 核心风险：判分模型 + 组件 License
一句话结论

技术上门槛不高，可以集成；但真正的工作量在"判得准"，不在"做得出来"。

平台已有的 应用中心（apps 表 + iframe）、文件上传（multer，xlsx 已在白名单）、 静态页托管 + exe 打包链路 三块地基完全够用，不需要引入任何新框架。

这类题判的是 OOXML 文档结构（合并单元格 / 字体 / 数字格式 / 公式 / 图表）， 与现有"题干选项文本比对"式判分不是同一套模型——这是唯一需要动到核心的地方。

1这道题到底要判什么

操作题不能靠"看答案对不对"来判，必须把每条要求翻译成可以在 OOXML 里定位的断言。 下表是我对这道题 4 个步骤的完整拆解：

步骤题面要求技术上要看的位置难度
1 A1:D1 合并及居中；输入标题"w市人口密度数据分析表"；隶书、加粗、17 号 sheet1.xml 的 <mergeCells>； styles.xml 的 <fonts>（name / b / sz）+ cellXfs 的 alignment ★★
2 D3:D13 用公式算常住人口密度（=常住人口*10000/土地面积）；数值型、不保留小数 sheet1.xml 单元格的 <f>（公式）与 <v>（值）； styles.xml 的 numFmt ★★
3 用函数求总土地面积、总常住人口，数值型不保留小数，放在 B14、C14 <f>SUM(...)</f> + 值 + 数字格式 ★
4 选中 A2:A13 与 D2:D13 生成簇状柱形图，标题"w市各地区人口密度"，作为其中对象插入 Sheet1 drawings/drawing1.xml + charts/chart1.xml： barChart / barDir=col / grouping=clustered / title / ser 的 <c:f> 引用 ★★★

这里藏着一个判分陷阱

题面说"结果设为数值型，不保留小数"。学生有两种都算对的实现：
① 直接 =C3*10000/B3，再把单元格数字格式设成 0 位小数（值仍是 7129.6051，只是显示 7130）
② 写 =ROUND(C3*10000/B3,0)（值直接变 7130）
如果判分器按"值必须等于 7130"去卡，方案①会被全判错。正确做法是值用 ±0.5 容差， 数字格式只作为"是否设了 0 小数"的独立评分点。这类细节决定整套系统能不能用。

我把平台现有的相关能力逐个核对了一遍，结论如下：

最重要的两条约束
  1. 部署形态把技术栈锁死了。Python 的 openpyxl 做 OOXML 判分体验最好， 但项目交付物是单文件 pkg 打包的 exe，不可能捆绑 Python 运行时。 所以判分引擎必须在 Node 侧实现——这一条排除了一半候选方案。
  2. 判分模型要从"布尔"升级为"评分点"。 is_correct tinyint(1) 表达不了"4 个评分点对了 3 个"。 这个改动会牵动 submit-test / submit-exam / practice 三条链路， 是本项目唯一有回归风险的部分（本项目已有"判分一律服务端裁定"铁律，改造时要遵守）。

由此得出的三个现实选择：

  1. 不追求"浏览器内完整还原 WPS"——成本最高、收益最低，且第 4 步的图表无论如何都要自己造。
  2. 若要在线模拟，图表自己用 ECharts（前端已装 recharts，但 ECharts 更适合）实现： 做一个"插入图表"对话框，学生选类型/数据区/标题，我们生成一个结构化的图表对象。 判分时它和真 WPS 导出的 chart1.xml 统一归一化成同一种中间表示。
  3. xlsx 导出自己写：不依赖 Univer Pro/SheetJS Pro。既然判分只认我们定义的评分点， 导出时可以只保证"能被自家判分器读懂"的 OOXML 子集——这就绕开了所有 License 限制。

5判分容错设计（决定"判得准不准"）

先看一个真实细节

这份样本文件里居然带着一条已经损坏的条件格式规则： <conditionalFormatting sqref="D3:D6"><cfRule ...><formula>#REF!</formula>。 更麻烦的是它还带着 WPS 特有的 XML 命名空间（xmlns:etc="http://www.wps.cn/..."）。 这说明真实的学生文件一定比规范文档脏——直接用严格 XML Schema 解析会当场崩掉。 判分器必须"按需取节点 + 全程容错"，绝不能假设文件结构干净。

下面 7 种情况我都见过或极易出现，"学生写法不同但都对"必须都给分：

#情况处理策略
1"不保留小数"的两种实现（ROUND vs 数字格式）值比对用 ±0.5 容差；"设了 0 位数字格式"单独作为一个评分点
2公式大小写、空格差异：=c3*10000/b3公式大小写不敏感、去空格后比对
3乘除顺序不同：=C3/B3*10000（数学等价）优先比计算结果值，公式字符串仅作参考，不做严格正则匹配
4SUM 写法多样：SUM(B3:B13) / 逐项相加 / 混合同样以值是否等于 6587 为主判据
5工作表被改名（Sheet1 → 其它）按"第几张表"或"包含目标数据区的表"定位，不绑死 Sheet 名
6图表标题取值位置不同（c:title 或 autoTitleDeleted）多路径兜底读取；标题为空且 chart 类型/数据区都对 → 给部分分
7WPS / Excel 导出的命名空间与属性差异用命名空间无关的解析（按 localName 匹配），不做字符串全等

6评分点方案（以本题为例，可直接落地）

3分
评分点 1 · 标题合并与格式
A1:D1 存在合并区；A1 文本 = "w市人口密度数据分析表"； 字体 name=隶书、bold=true、size=17；水平居中。
4分
评分点 2 · 人口密度公式（D3:D13）
11 个单元格逐个判定：值 ≈ 标准答案（±0.5）得 0.3 分/格； 且公式引用了本行 C 列与 B 列。共 3.3 分，向上取整 4 分。
3分
评分点 3 · 合计行（B14 / C14）
值分别 ≈ 6587 与 931（±0.5）；理想情况使用 SUM 函数（用函数再加 0.5 分， 但值对即给基础分——避免"用逐项相加也算对"被误判）。
1分
评分点 4 · 数字格式
D 列与 B14/C14 的 numFmt 为 0 位小数（或值为已取整的整数）。
4分
评分点 5 · 簇状柱形图
存在图表对象且锚定在 Sheet 内 → 1 分； barDir=col 且 grouping=clustered → 1 分； 标题为"w市各地区人口密度" → 1 分； 数据区覆盖 A2:A13（分类轴）与 D2:D13（数值轴）→ 1 分。按项累加，允许部分得分。

合计 15 分。分档给分的好处是：学生"做对 3 步、图表只画了一半"也能拿到大部分分， 反馈里能精确告诉他错在哪个评分点——这才是操作题对教学真正的价值。

判分引擎骨架（Node）

// 依赖：yauzl(已装) + exceljs + fast-xml-parser
const ExcelJS = require('exceljs');

// 1) 语义层：单元格 / 字体 / 数字格式 / 合并
async function readSheet(buf) {
  const wb = new ExcelJS.Workbook();
  await wb.xlsx.load(buf);
  const ws = wb.worksheets[0];              // 不绑死 Sheet1 名字
  const merges = ws.model.merges;            // ['A1:D1']
  const a1 = ws.getCell('A1');
  return {
    title: a1.value,
    font: { name: a1.font?.name, bold: a1.font?.bold, size: a1.font?.size },
    halign: a1.alignment?.horizontal,
    merges,
    formula: ws.getCell('D3').formula,   // 'C3*10000/B3'
    d3: ws.getCell('D3').value,
  };
}

// 2) 图表层：exceljs 不支持 → 自己解 chart1.xml
//    用 yauzl 取出 xl/charts/chart1.xml，按 localName 取节点（忽略命名空间）
function checkChart(xml) {
  const ns = x => x;                        // 命名空间无关解析
  return {
    isBar:        /<[\w:]*barChart[\s>]/.test(xml),
    isColumn:     /barDir[^>]*val="col"/.test(xml),
    isClustered:  /grouping[^>]*val="clustered"/.test(xml),
    title:        (xml.match(/<[\w:]*title[\s\S]*?<[\w:]*t[^>]*>([^<]+)/) || [])[1],
    refs:         [...xml.matchAll(/<[\w:]*f>([^<]+)<\/[\w:]*f>/g)].map(m => m[1]),
  };
}

// 3) 容错比对：值优先 + 容差

7风险清单

8结论与建议

能不能做？能。而且不用动平台框架——应用中心、文件上传、静态页托管与 exe 打包链路都已就绪。

要投多少？一期（模板下载 + 上传判分 + 逐点回执）约 1~2 周， 核心是写一个 OOXML 判分引擎和一套"评分点定义"数据结构。二期在线模拟视需要再定。

最该先做的三件事（按顺序）：

  1. 先做判分引擎的 PoC：拿这份 人口密度数据分析表.xlsx 的正确版本 + 2~3 个"故意做错"的版本， 验证能否准确区分"全对 / 漏做图表 / 公式对但没设小数位"。
  2. 再定"评分点定义"的存储格式（建议 JSON 存在题干旁边），这是操作题的题库核心， 比界面重要得多。
  3. 最后接界面：一期用"下载模板 + 上传文件"最简形态即可上线验证教学效果， 不要一开始就做在线编辑器。
