仅剩的边界（占比极小）
  • 窗体 / 报表 / 宏 / 模块：只能判"对象是否存在"，内部控件与布局读不到（63 题中未出现）。
  • 字段显示格式（短日期 / 长日期 / 是-否格式）：存在表属性流里，机制与排序相同，一期一并实现并实测。

二、技术路径

交付物是单文件 pkg exe，运行环境装不下 Python，也不能假设学生机装了 Office/ACE 驱动，因此判定引擎必须纯 Node。 mdb-reader 是唯一成熟的纯 JS Access 读取库：

  • 许可 MIT，可商用可打包；依赖仅 fast-xml-parser/browserify-aes/create-hash/pako，全纯 JS；
  • 格式覆盖 Access 97 (Jet3) → 2019 (ACE17)，.mdb 与 .accdb 通吃（学测老题多为 .mdb）；
  • 支持带密码库解密；Node 22 下 require() 实测可用，pkg 打包风险低。

它唯一缺的是索引 / 主键——而这恰好是学测最高频的操作点，因此我们自己补了这一块（见下节）。

三、主键突破（本轮核心）

主键可以完整读出：是否存在、在哪一列、升序还是降序、是否多列。 Access 把主键存成 表的 TDEF（表定义）页里的一条索引，mdb-reader 会整段跳过；我们按 jetdb（Rust 实现）的 TDEF 索引布局自行解析，实测通过。

四、排序 / 筛选

Access 数据表视图的排序与筛选不改变物理存储顺序，但会写入表的 LvProp 属性流。 该属性流的属性名清单实测包含 Filter · OrderBy · OrderByOn · Format · InputMask · DefaultValue 等——

  • 排序 OrderBy：已实测读出 "[奖牌榜].[奖牌总数] DESC"（冬奥会样卷四步之一，判定通过）。
  • 筛选 Filter：与排序同机制、同一属性流，FilterOn 表示是否启用。一期按同法实现。
  • ⚠️ 属性流里的字符串没有 2 字节对齐，扫描 UTF-16 必须双奇偶（phase 0/1），否则全错位——这是实现时的关键坑。

七、新增的产品需求（本批题面暴露）

① 一次提交多个文件

第 4 / 12 / 22 / 23 / 27 / 29 / 46 / 61 题要求额外上传导出文件（如 大于400.txt、优秀学生.xlsx）。 题面已明确"如果题目要求上传多个文件，请依次上传全部所需文件"。

→ 学生端提交需支持 accdb + 若干 txt/xlsx；accdb_export 检查器对导出文件判分。

② 导出文件判分可复用 WPS 引擎

导出的 xlsx 直接交给现有 wps-grader.js；txt 为分隔文本， 只需按"字段名 + 行内容（可带格式与布局）"比对。

→ 无需新造格式解析，只需一个薄适配层。

八、风险与分期

风险

  • 字段格式类属性（短日期/长日期/是否格式/输入掩码）：存在属性流，机制与排序相同，但属性名到取值的映射需一期实测固件，留出调试时间。
  • pkg 打包 ESM：Node 22 实测可行，仍需 CI 出包后回归；必要时把 mdb-reader 源码内联进主工程（MIT 允许）以规避 exports 限制。
  • 文件体积：accdb 通常几百 KB ~ 数 MB，上传限额建议放宽到 ≥ 50 MB。
  • 学生交空库/坏库：解析失败判 0 并提示"文件无法识别"，不抛异常。

建议分期

  • 一期：表 / 字段 / 字段类型 / 主键 / 记录 / 排序 / 筛选 七类 + 教师上传标准库自动出骨架 + 学生上传判分。可覆盖全部 63 题的 90% 以上操作。
  • 二期：导出文件（accdb_export，复用 WPS 引擎）/ 查询 / 关系 / 字段格式属性 / 窗体报表存在性。
  • 复用：视频演示、多模板、练习情况统计、ACCESS 分栏外壳等，WPS 分支已做好，Access 直接共用。
